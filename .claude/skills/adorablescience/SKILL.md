# Adorable Science: working on the app

**What it is:** fuzzy-hearted, well-sourced science news. Anyone signs up and writes articles; **nothing is published until a Lab Director (admin) approves it**; approved articles appear on the front page.
- Stages: `draft` (🧫 In the Petri dish) → `pending` (🔬 Under the microscope) → `published` (🚀) or `rejected` (🧪 Needs more data, with the reviewer's note). Editing a published article takes it off the front page until approved again.
- Sources are strongly encouraged: live citation meter, one-click `[1]` inline citations, a "no sources?" warning on submit, an "Unsourced" badge, an automatic reviewer checklist.
- Writer profiles (`#writer/<id>`) with stats and badges; Writers page; **boops** 🐾 (likes); Directors can feature an article.
- The **first person to sign in becomes the first Lab Director**; Directors promote others (Review desk → Lab members).

**Where it lives:**
- App repo **github.com/arkulinskis/adorablescience**, branch `master`; Anvil pulls master. Live: https://adorablescience.com (per apps.json).
- This folder **is** the Anvil repo ("git" layout). README.md has the full feature list and formatting syntax.

**What the user wants:** the interface should feel like a mix of adorable and science (Fredoka headings, Nunito text, Space Mono labels; Bea-the-Beaker mascot and spinner). Creative, assumed details welcome. Claude deploys.

**Page pattern:** one Form per page with `<anvil-form layout="Adorable_Science.Layouts.Shell">`, data loaded in
`__init__` with `api.load(...)`, buttons call `state.call(...)`. Server functions are `@api(...)` and raise
`Oops("friendly message")` for expected problems (they come back as `{"__oops__": msg}`).

**Tables:** `users` (+ uid, display_name, avatar, specialty, bio, website, is_admin, legal_*), `articles` (specimen_no,
dek, body, category, evidence, status, reviewer, review_note, featured, boops, source counts, study_subject,
study_size, caveat), `sources`, `boops`, `lab_log`.

## Recipes

- **New server function:** `@api(user=True)` (or `admin=True`) in the right module; use Lab helpers (`me()`,
  `get_article_row`, `card`, `full_article`); raise `Oops` for user errors; log important actions with `log(...)`.
- **New page:** `client_code/Pages/<Name>/` (form_template.html + __init__.py), register it in router.py.
- **New column:** anvil.yaml db_schema, read it with `Lab.opt(row, col)` and write with `Lab.put_opt(row, col=v)` so the
  live app keeps working until the user accepts the Schema Mismatch.
- **Public page / feed change:** server_code/Public.py (inline CSS, light + dark; escape with html.escape; body via
  Render.markdown). Never build it from full_article (that one reads the viewer).
- **Article formatting:** extend Render.py (escape first) and the README's formatting line.

## Gotchas

- **Continue with Google** (client_code/auth.py): `login_with_google()` returns None for someone without an account,
  so the code then calls `signup_with_google()`; on the sign-up view it needs the Privacy & Terms tick first.
- No Email service in this app: adding notifications by email means adding the service + legal kit facts.
- Local tests: since the admin_emails rollout only `admin@example.com` (ui_test.py passes it as the secret) becomes a
  Lab Director; tools/ui/lib.js still signs in director@example.com, so its director scripts need updating.
- The Docker App Server here could reach api.crossref.org (2026-11-20), so the retraction check really runs locally.
- `python -I` hides PyYAML: run gitapp_check/gitapp_test without `-I`. `tools/assets.py` rewrites anvil.yaml in block
  style (big diff): patch the `?v=` hash by hand if you want a small diff.
